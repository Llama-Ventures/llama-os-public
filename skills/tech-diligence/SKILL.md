# Tech Diligence — 技术方向深度调研 Skill

> 定位：对一个**技术方向/赛道**进行系统性调研，产出 Technology Landscape Report

---

## 一、Skill 定义

### 1.1 是什么
当Llama Ventures进入一个新的技术赛道时，用结构化框架快速建立对该技术方向的完整认知：技术本质是什么、有哪些流派在竞争、从哪来到哪去、谁在做、IP格局如何、成熟度到哪了、投资机会在哪。

### 1.2 不是什么
- 不是对单个公司的DD（公司级DD是独立的后续步骤）
- 不是学术综述（我们关注投资含义，不是技术细节的穷尽）
- 不是市场报告（我们从技术出发，但最终落到投资判断）

### 1.3 与公司级DD的协作关系

本技能产出赛道级上下文，供对单个公司做DD时参考：

```
tech-diligence (赛道级)          公司级DD
─────────────────────           ────────────────
M3 流派对比        ──引用──→    行业分析
M5 生态图谱        ──引用──→    竞争格局
M7 技术成熟度      ──引用──→    技术评分
M8 投资含义        ──引用──→    Investment Thesis
```

---

## 二、触发条件

以下情况触发本技能：
1. 用户说"调研一下XX技术/赛道/方向"
2. 用户说"给我做一个XX的技术landscape"
3. 用户说"XX这个领域怎么样？值得看吗？"
4. 用户说"帮我理解XX技术"
5. 用户提供了一个技术方向名称 + 要求系统性分析
6. 用户说"tech diligence" / "技术调研" / "赛道调研"

**不触发**的情况：
- 用户只是问一个技术概念的定义（直接回答即可）
- 用户要求对某家公司做DD（走公司级DD流程）
- 用户要求写代码或做工程实现

## 三、8模块框架

### 模块总览

| 模块 | 代号 | 名称 | 核心问题 | 产出 |
|:----:|:----:|------|---------|------|
| M1 | Primer | 技术本质 | 这个技术到底在干什么？ | 技术原理简报 |
| M2 | Taxonomy | 领域全景 | 领域长什么样？ | 技术栈全景图 + 价值链 |
| M3 | Schools | 流派对比 | 有哪些解法？谁在赢？ | 多维对比矩阵 + 下注判断 |
| M4 | Lineage | 起源脉络 | 从哪来？关键转折？ | Timeline + 学术谱系 |
| M5 | Ecosystem | 生态图谱 | 谁在做？做到什么程度？ | Ecosystem Map |
| M6 | IP | 专利与知识产权 | 谁拥有什么？有没有IP地雷？ | 专利格局分析 |
| M7 | Maturity | 技术成熟度 | 离大规模商用多远？ | TRL评级 + 时间估算 |
| M8 | Thesis | 投资含义 | 投资机会在哪？ | Bull/Bear + 理想标的画像 |

### 执行顺序

```
Phase 1: 建立认知基础
  M1 技术本质 → M2 领域全景

Phase 2: 理解路线和历史
  M3 流派对比 → M4 起源脉络

Phase 3: 扫描玩家和IP
  M5 生态图谱 → M6 专利IP

Phase 4: 判断时机和机会
  M7 技术成熟度 → M8 投资含义
```

### 模块间依赖关系
```
M1 ──→ M3 ──→ M5 ──→ M8
 ↓       ↓       ↓       ↑
M2      M4      M6      M7
```
- M1/M2 是基础层，必须先完成
- M3 依赖 M1（理解技术才能比较流派）
- M5 依赖 M3（知道流派才能分类公司）
- M8 依赖所有前置模块

## 四、各模块详细说明

### M1 技术本质 (Technology Primer)

**目的**：用投资人能理解的语言建立第一性原理认知。

**执行清单**：
1. **问题定义**：这项技术解决什么根本问题？为什么之前解决不了？现在为什么能解决了？
2. **核心原理**：用类比和非技术语言解释工作原理（目标：LP能听懂）
3. **输入→输出**：技术系统的输入是什么、输出是什么、中间发生了什么
4. **关键术语表**：5-15个必须掌握的核心概念，每个用1-2句话解释
5. **技术边界**：这项技术能做什么、不能做什么、常见误解是什么
6. **类比锚点**：找一个大家都懂的技术作为类比（例：世界模型之于物理世界 ≈ LLM之于语言世界）

**参考模板**：`references/technology-primer-template.md`

---

### M2 领域全景 (Field Overview & Taxonomy)

**目的**：画出领域的"地图"——技术栈、子领域、价值链。

**执行清单**：
1. **技术栈分层**：从底层到上层，识别3-7层技术栈
2. **子领域划分**：赛道内的细分方向及各自边界
3. **相邻领域**：哪些技术领域有交叉、竞争、或互补关系
4. **价值链分布**：每一层的商业化模式、利润率、价值捕获点
5. **市场规模**：按子领域拆分的TAM/SAM估算（附数据源）
6. **产业链角色**：供应商、平台、应用商、终端用户的关系

**参考模板**：`references/field-taxonomy-template.md`

---

### M3 流派对比 (Schools of Thought)

**目的**：识别技术路线分歧，为投资押注提供判断依据。**这是本框架最关键的模块。**

**执行清单**：
1. **流派识别**：识别2-5个主要技术路线/范式，命名并简述
2. **哲学差异**：每个流派的底层信仰/假设是什么
3. **多维对比矩阵**：在以下维度对比：
   - 性能上限
   - 当前成熟度
   - 数据需求量
   - 计算成本
   - 可扩展性
   - 商业化难度
   - 代表公司/团队
4. **历史先例**：找1-2个历史上类似的"路线之争"，分析最终结局
5. **收敛 vs 分化**：判断这些流派是趋同还是长期共存
6. **下注判断**：作为VC应该押哪个流派？什么条件下翻转？

**参考模板**：`references/schools-of-thought-template.md`

---

### M4 起源脉络 (Evolution & Lineage)

**目的**：理解技术的时间维度——从哪来、经过什么、要去哪。

**执行清单**：
1. **起源论文/时刻**：哪篇论文、哪个事件开启了这个方向
2. **里程碑时间线**：按年份标注关键突破（论文、产品、商业化节点）
3. **范式转换**：经历过几次方法论的根本性转变
4. **学术谱系**：关键研究者的师承关系、实验室脉络
5. **技术代际**：当前是第几代技术？每代的核心改进是什么？
6. **从实验室到产品**：这个领域学术→产品的典型转化路径和时间周期
7. **S曲线定位**：当前在技术S曲线的哪个阶段（萌芽/加速/成熟/衰退）

**参考模板**：`references/evolution-lineage-template.md`

---

### M5 生态图谱 (Ecosystem Map)

**目的**：扫描所有玩家，建立竞争全景。

**执行清单**：
1. **公司地图**：按 [流派 × 技术栈层级] 分类，列出：
   - 公司名 + 一句话描述
   - 融资轮次/金额/估值
   - 阶段（研究/产品/商业化）
   - 技术路线归属
2. **大厂布局**：Google/Meta/NVIDIA/Microsoft/Apple/Amazon各自的下注
3. **学术重镇**：Top 5-10实验室及其代表成果
4. **开源生态**：关键开源项目（名称、Stars、活跃度、商业化模式）
5. **人才流向**：顶级研究者的流动方向（学术→哪家公司？公司间如何流动？）
6. **会议与发表**：核心学术会议的发表量趋势
7. **资本动态**：近12个月的融资事件汇总、资本流向哪些子方向

**参考模板**：`references/ecosystem-map-template.md`

---

### M6 专利与知识产权 (IP Landscape)

**目的**：评估IP格局，识别FTO风险和专利壁垒。

**执行清单**：
1. **专利量趋势**：近5年专利申请量变化曲线
2. **专利持有者排名**：Top 10-15专利持有方
3. **专利地理分布**：美国/中国/欧洲/日韩的申请分布
4. **关键专利簇**：有没有绕不过去的基础专利？
5. **IP集中度**：集中（少数玩家垄断）vs 分散（竞争开放）
6. **开源 vs 闭源格局**：核心技术的开源程度，对创业公司的影响
7. **FTO风险评估**：新创公司进入这个领域的IP障碍有多高

**数据源建议**：Google Patents, USPTO, Lens.org, PatSnap, Espacenet

**参考模板**：`references/ip-landscape-template.md`

---

### M7 技术成熟度 (Technology Maturity)

**目的**：判断技术在生命周期中的位置，指导投资timing。

**执行清单**：
1. **TRL评级**：Technology Readiness Level（1-9），逐级评估
2. **Hype Cycle定位**：在Gartner Hype Cycle的哪个阶段
3. **采用曲线定位**：Innovators / Early Adopters / Early Majority / Late Majority
4. **剩余硬问题 Top 5**：还有哪些未解决的核心技术挑战
5. **量产/规模化障碍**：从Demo到大规模部署的关键障碍
6. **成本曲线**：单位成本的下降趋势和驱动因素
7. **时间估算**：距离主流采用的估算（1年/3年/5年/10年+），附假设条件
8. **对标历史**：找一个已经走完成熟度曲线的类似技术做对比

**参考模板**：`references/technology-maturity-template.md`

---

### M8 投资含义 (Investment Implications)

**目的**：把前7个模块的分析收束为投资决策指导。

**执行清单**：
1. **价值捕获分析**：技术栈中哪一层最容易建壁垒、捕获价值
2. **投资时机判断**：
   - 现在是投这个方向的好时候吗？
   - 什么信号出现意味着"该投了"？什么信号意味着"太早/太晚"？
3. **技术风险矩阵**：列出3-5个关键技术假设，评估各假设失败的概率和后果
4. **流派下注建议**：
   - 集中押一个流派 vs 分散下注
   - 如果只能投一家，投哪种公司
5. **理想标的画像**：在这个赛道中，值得投的公司应该具备什么特征
   - 团队：什么背景
   - 阶段：Pre-seed/Seed/A
   - 技术选择：哪个流派
   - 数据策略：如何建数据壁垒
   - 商业化：什么GTM路径
6. **Bull/Bear Case**：整个技术方向的多空论据
   - Bull：为什么这个方向会成？
   - Bear：为什么可能不成？
   - 翻转条件：什么事件会让Bull变Bear或反过来？
7. **Portfolio 关联（如你有相关已投项目）**：你的组合中谁受益/受威胁于这个技术方向

**参考模板**：`references/investment-implications-template.md`

## 五、执行模式

### 5.1 Full Report（完整报告）

触发词："完整调研" / "full report" / "全面分析"

执行 M1→M2→M3→M4→M5→M6→M7→M8 全部模块，产出完整的 Technology Landscape Report。

适用场景：
- 首次进入一个全新赛道
- IC前需要完整的赛道级分析
- 准备赛道thesis presentation

### 5.2 Quick Scan（快速扫描）

触发词："快速看一下" / "quick scan" / "大概什么情况"

执行 M1 + M3 + M7 三个模块（技术本质 + 流派对比 + 成熟度），产出 2-3 页的快速概览。

适用场景：
- 刚收到一个新赛道的Deck，需要快速建立context
- 需要快速回答"XX赛道怎么样"
- 判断一个赛道是否值得深入调研

### 5.3 Module-Specific（指定模块）

触发词："只看流派对比" / "给我画个生态图" / 明确指定模块名

只执行指定的模块，产出该模块的分析。

适用场景：
- 已经对赛道有基础了解，只需要补充特定维度
- 为公司级DD补充赛道上下文
- 准备特定主题的讨论材料

## 八、质量标准

### 8.1 每个模块必须满足
- [ ] 所有事实性陈述标注来源（[论文] / [公司官网] / [融资数据] / [推断]）
- [ ] 推断与事实严格区分，推断标"推断"
- [ ] 数字附单位和时间（"$1B融资" → "$1B融资（2025年10月）"）
- [ ] 中英文术语首次出现时双语标注（例：世界模型 World Models）

### 8.2 整体报告必须满足
- [ ] M8投资含义直接引用M1-M7的具体发现，不空泛
- [ ] Bull/Bear Case有具体的触发条件和翻转逻辑
- [ ] 理想标的画像足够具体，能用来筛选Deck
- [ ] 对已投Portfolio的关联分析（如适用）

### 8.3 禁止项
- 不编造融资数据、专利数量等需要精确来源的信息
- 不写"前景广阔"等无信息量的结论
- 不回避不确定性——不知道就标❓，推断就标"推断"
- 不为了填满模块而注水——如果某个模块信息不足，标注"信息不足，需进一步调研"
