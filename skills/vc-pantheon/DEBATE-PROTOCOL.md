# VC Pantheon — 辩论协议 (Debate Protocol)

> 结构化的虚拟投资人辩论系统。目标不是达成共识，而是通过碰撞暴露盲点、强化论证。

## 一、辩论模式菜单

### Mode A: 快速对决 (Quick Clash) — 2人，10分钟
**用途**：快速暴露一个项目的核心矛盾
**格式**：
- Bull vs Bear
- 各 3 轮发言
- 直接交锋，不绕弯

```
触发："/debate quick [项目名]"
或："让 XX 和 YY 快速对一下"
```

### Mode B: 圆桌评估 (Roundtable) — 3-5人
**用途**：标准 deal 评估，多维度覆盖
**格式**：
- 每人独立评估 → 交叉质疑 → 综合矩阵
- 4 轮：立场宣言 → 最大分歧交锋 → 反驳 → 终局判断

```
触发："/debate [项目名]"
或："多视角评估一下 XX"
```

### Mode C: IC 模拟 (IC Simulation) — 5-10人
**用途**：重大决策前的完整模拟
**格式**：
- 完整 IC 流程：项目汇报 → 提问 → 讨论 → 投票
- 包含角色分工：主讲人、行业专家、Devil's Advocate、创始人评估专家
- Llama 自身视角最后发言

```
触发："/debate ic [项目名]"
或："模拟一下 IC 讨论"
```

### Mode D: 认知碰撞 (Cognitive Collision) — 2-3人
**用途**：不是评估具体项目，而是讨论一个赛道/趋势/投资方法论
**格式**：
- 开放式讨论
- 每人带着自己的 thesis 入场
- 目标是形成更深的理解，不是做投资决策

```
触发："让 XX 和 YY 讨论一下 [赛道/趋势/方法论]"
```

## 二、辩论执行流程

### Phase 0: 选人与准备

1. **自动推荐**（参见 RECOMMENDATION-ENGINE.md）或用户指定
2. **加载投资人档案**（完整 profile + tags）
3. **加载项目信息**（所有已知 facts）
4. **预判分歧点**（基于投资人标签推测最可能的分歧维度）

### Phase 1: 独立评估 (Independent Assessment)

每位投资人独立评估，不看其他人的观点。输出：

```markdown
### [投资人名] — 独立评估

**一句话判断**：INVEST / PASS / WAIT / NEED DATA

**核心论点**（3-5 条）：
1. [argument with evidence]
2. [argument with evidence]

**最大担忧**：[specific concern]

**关键假设**：[what must be true for this to work]

**愿意承受的风险**：[what downside is acceptable]

**估值观点**：[on pricing]

**给 Llama 的建议**：[specific to Llama's situation]

**信心度**：1-10（10=极度确信）
```

### Phase 2: 交叉质疑 (Cross-Examination)

系统识别出最大分歧点，组织投资人直接对话。

**分歧识别规则**：
- 如果有人说 INVEST 而有人说 PASS → 这是核心分歧
- 如果关键假设矛盾 → 组织直接对话
- 如果对市场规模/竞争格局判断不同 → 组织数据对质

**交叉质疑格式**：
```
[投资人A]：你说 [观点X]，但你有没有考虑过 [挑战Y]？
[投资人B]：[直接回应]。反过来问你：[反向挑战]。
[投资人A]：[回应或承认]。
```

**规则**：
- 必须直接回应对方的论点，不能顾左右而言他
- 可以改变立场——如果被说服了要大方承认
- 数据和逻辑优先于权威和经验

### Phase 3: 终局判断 (Final Verdict)

每位投资人在听完所有讨论后，给出最终判断：

```markdown
### 终局判断矩阵

| 投资人 | 初始立场 | 最终立场 | 立场变化原因 | 信心度 |
|--------|---------|---------|------------|-------|
| [A] | INVEST | INVEST | 未改变 | 8/10 |
| [B] | PASS | WAIT | 被 [A] 关于 [X] 的论点部分说服 | 5/10 |
| [C] | WAIT | INVEST | [讨论中发现 Y 是成立的] | 7/10 |
```

### Phase 4: Llama 综合 (Llama Synthesis)

**最后由 Llama 自身视角做综合**：

```markdown
## Llama Ventures 综合判断

### 辩论中最有价值的洞察
1. [来自投资人X] — [洞察]
2. [来自投资人Y] — [洞察]

### 我们同意谁？为什么？
- 与 [投资人A] 的观点最共鸣，因为 [reason aligned with Llama philosophy]

### 我们不同意谁？为什么？
- 不同意 [投资人B] 关于 [X] 的判断，因为 [Llama's unique perspective]

### 辩论暴露的盲区
- 我们之前没有考虑到 [issue raised by investor C]
- 需要进一步验证：[specific data/info needed]

### 行动建议
1. [next step 1]
2. [next step 2]

### 信心度变化
- 辩论前：[X]/10
- 辩论后：[Y]/10
- 变化原因：[explanation]
```

## 三、辩论质量标准

### 好的辩论特征
- ✅ 至少有一个根本性分歧被充分展开
- ✅ 有投资人在讨论中改变了立场
- ✅ 产生了至少一个之前没有考虑过的视角
- ✅ 最终综合中有明确的行动建议
- ✅ 数据和逻辑驱动，不是"我觉得"

### 差的辩论特征
- ❌ 所有人都同意 → 没有价值
- ❌ 分歧很大但没有直接交锋 → 各说各话
- ❌ 讨论停在抽象层面，没有落到项目具体 facts
- ❌ 没有产生新的认知
- ❌ Llama 综合只是简单汇总，没有自己的判断

## 四、预设辩论组合（经典对决）

### 🥊 哲学 vs 数据
**Peter Thiel vs 沈南鹏**
- Thiel 从哲学/垄断切入，沈南鹏从数据/执行切入
- 最适合：判断一个项目是"0到1"还是"品类冠军竞争"

### 🥊 乐观 vs 审慎
**Marc Andreessen vs David Sacks**
- Andreessen 极度乐观"软件吃掉一切"，Sacks 关注资本效率和泡沫
- 最适合：判断一个高增长高烧钱项目是否值得投

### 🥊 技术 vs 商业
**Vinod Khosla vs Bill Gurley**
- Khosla 看技术突破，Gurley 看商业模式和市场经济学
- 最适合：Deep tech 项目的商业可行性辩论

### 🥊 短期 vs 长期
**朱啸虎 vs 张磊**
- 朱啸虎"三个月见分晓"，张磊"超长期主义"
- 最适合：中国市场项目的投资时间框架辩论

### 🥊 平台 vs 应用
**Chris Dixon vs Martin Casado**
- Dixon 看平台潜力和技术浪潮，Casado 看基础设施成本和利润率
- 最适合：AI 公司是平台还是功能的辩论

### 🥊 创始人 vs 市场
**徐小平 vs Don Valentine**
- 徐小平"投人就是投梦想"，Valentine"市场大于一切，创始人可替换"
- 最适合：创始人很强但市场不确定的项目

### 🥊 中美视角碰撞
**沈南鹏 vs Marc Andreessen**
- 中国互联网最强投资人 vs 硅谷最强投资人
- 最适合：跨境项目、中国创始人做全球市场

### 🥊 用户挑战赛
**用户视角 vs [任意投资人]**
- 用用户自己的投资判断与 Pantheon 中任意投资人辩论
- 最适合：用户已有判断，想要被挑战和压力测试

## 五、辩论后沉淀

每次有价值的辩论结果应被捕获：

1. **新的认知洞察** → 保存到知识库或笔记系统
2. **方法论改进** → 整理成你的方法论文档的更新建议
3. **投资人档案更新** — 如果辩论中发现某投资人的模拟不够准确
4. **项目判断记录** → 保存到项目笔记或 brief 系统（deal-specific 或跨 deal 的判断）
