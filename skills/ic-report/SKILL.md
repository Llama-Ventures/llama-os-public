# IC Report — 投资委员会视觉报告

将已有的 DD 材料（笔记、会议记录、Deck、截图）转化为一个可以直接给 partner 看的 HTML 报告。

---

## 设计哲学

### 1. Presentation first，不是 Document first

这不是一份研究报告，是一份要在 partner 面前讲的东西。设计的第一原则是：**每一屏都能独立讲一个点**。

- 每个看人看事的问题独占一个视觉区块（`qa-slide`），相当于 PPT 的一页
- 读者可以从任何一页开始看，不需要从头读到尾
- 文字密度低。如果一段话超过三行，想想能不能用卡片、双栏、列表替代

### 2. 每个回答都有"本质"

这是和普通 DD memo 最大的区别。看人看事 12 个问题，每个问题回答完之后，都有一个**"本质"框**——用一两句话穿透这个问题的核心洞察。

**为什么这很重要：**
- Partner 可能不会读完每个问题的详细回答，但一定会扫"本质"框
- 逼自己提炼本质的过程本身就是思考的质量检验——写不出本质，说明还没想清楚
- 本质框的风格参考一位资深合伙人的评审风格：有观点、有立场、一句话说到底

**"本质"框设计：**
- 左边框加粗（橙色/accent 色），背景微暖色
- 字体用衬线体（宋体），比正文大一号，加粗
- 顶部有小标签"本质"

### 3. 图文并茂

一个没有图片的 IC 报告是不完整的。图片不是装饰，是证据。

**应该有的图片：**
- 产品渲染图 / 实物照（从 Deck 提取或现场拍）
- 创始人照片 / 团队页（从 Deck 提取）
- 现场访问照片（工作室、demo、和创始人的合影）
- 社交媒体截图（Instagram、推特用户反应——作为牵引力证据）
- 竞品实物照
- 行业地图（如有交互式版本，用 iframe 嵌入）

### 4. 避免绝对性描述

绝对性的描述很容易是错的。在报告中：
- "唯一" → "很少见"
- "没有一家" → "目前尚未看到"
- "所有竞品" → "目前主要竞品"
- "无法被复制" → "很难被复制"
- "极深" → "很深"

投资判断需要 conviction，但 conviction 不等于绝对化。有把握的地方可以说得强，不确定的地方如实标注。

### 5. 浅色暖色调

- 底色：米白/暖灰（`#faf9f7`），不是冷白
- 正文：深灰（`#3d3d3d`），不是纯黑
- 强调色：暖橙（`#c05d3a`）——用于本质框、标签、问题编号
- 绿/黄/红信号灯色用饱和度适中的色调，不要荧光感
- 标题用衬线体（Noto Serif SC），正文用无衬线（Noto Sans SC）
- 大量留白。留白是设计，不是浪费空间

### 6. 全中文

报告面向中文读者（投资决策者）。所有英文术语都应翻译：
- Founder-Market Fit → 创始人-市场匹配度
- Traction → 牵引力
- Unit Economics → 单位经济
- Pre-seed → 种子前轮

但保留专有名词：公司名、产品名、品牌名等不翻译。

## 报告结构

```
1. 封面
   - 公司名、副标题、报告人、日期、信息来源
   - 产品主视觉图

2. 投资本质
   - 一段话说清"投资人在赌什么"
   - 这是整份报告的灵魂，要反复打磨

3. 范式转移 / 为什么是现在
   - 历史 timeline（品类演进）
   - 市场规模（用市场级数字，不是单个公司收入）
   - 为什么这个时间窗口

4. 基本事实（精简）
   - 公司 + 融资（双栏卡片）
   - 产品 + 单位经济（双栏卡片）
   - 技术亮点（表格，和竞品对比）
   - 牵引力（大数字 + 截图证据）
   - 关键时间节点（timeline）
   - 竞品格局（彩色卡片，每个竞品一张）
   - 行业地图（iframe 嵌入交互式版本）

5. 看事 · 六步（每步一个 qa-slide）
   01 亲身体验
   02 行业位置
   03 核心识别
   04 能力结构
   05 红黄绿灯
   06 一句话

6. 看人 · 六步（每步一个 qa-slide）
   01 人物前传
   02 三个 Why
   03 能力结构
   04 理解深度
   05 性格与主观判断
   06 创始人-市场匹配度

7. 综合判断
   - 信号灯总表
   - Llama Edge
   - 信息缺口
   - 下一步
```

## 视觉组件

### qa-slide（看人看事问题卡片）
```
┌─────────────────────────────────┐
│ 01   问题标题                    │  ← 大号编号 + 标题
│      副标题（原始问题）            │  ← 小字灰色
│                                  │
│  回答内容                         │  ← 卡片/双栏/列表/图片
│  ...                             │
│                                  │
│  ┃ 本质                          │  ← 橙色左边框
│  ┃ 一两句话穿透核心               │  ← 衬线体、加粗
└─────────────────────────────────┘
```

### 竞品卡片
```
┌─ 红色顶边 ─────────────┐
│ 标签（如"最接近的竞品"）  │
│ 公司名                   │
│ 关键数据                  │
│ 差异点                    │
└─────────────────────────┘
```
每个竞品一个颜色，2x3 网格排列。

### 信号灯表
绿/黄/红圆点 + 维度 + 信号描述，简洁的表格。

### 本质框（大号版）
```css
.essence-lg {
  background: var(--warm);      /* 暖灰底 */
  border-left: 4px solid var(--accent);  /* 橙色左边框 */
  padding: 1.5rem 2rem;
  border-radius: 0 8px 8px 0;
}
.essence-lg p {
  font-family: 'Noto Serif SC', serif;  /* 衬线体 */
  font-size: 16px;
  font-weight: 500;
}
```

## 流程

1. **收集材料** — DD 笔记、会议记录、Deck PDF、截图、对话记录
2. **提取图片** — 从 Deck 提取关键页面为 PNG，收集现场照片、社交截图
3. **写文字稿** — 先在 markdown 里把内容写完（本质 > 范式 > 事实 > 看事 > 看人 > 判断）
4. **打磨本质** — 每个看人看事问题的"本质"框要反复推敲，这是报告质量的核心
5. **生成 HTML** — 填入模板，插入图片，调整布局
6. **Review** — 打开浏览器检查：图片加载、文字密度、每屏独立性
7. **同步** — markdown 版本同步更新

## 核心理念总结

> **报告是给人看的，不是给人读的。** 每一屏独立、图文并茂、本质穿透。
> 决策者花 5 分钟扫完所有"本质"框，就应该能理解这个 deal。
> 花 30 分钟从头到尾看完，应该觉得自己做了一次深度思考。
