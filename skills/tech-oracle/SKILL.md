# Tech Oracle — 技术判断力

> **核心理念**：投资人不需要比创始人更懂技术。投资人需要比其他投资人更快、更准确地理解"这个技术能做什么，不能做什么"。

## 设计哲学

核心理念：**技术判断力 AI 化 → 快速达到"足够的技术理解"**。

它不是万能的——它帮你在 10 小时内达到"足够理解"，让你能跟技术专家进行有质量的对话，而不是被创始人的技术叙事牵着走。

## 五个核心能力

### 1. 技术声称评估 (Claim Assessment)

给定一个创业公司的技术声称，评估其可信度。

**输入**：创始人说"我们的模型比GPT-4快10倍，成本低100倍"
**输出**：
- 可信度评分（1-10）+ 理由
- 类似声称的历史对比（谁说过类似的话？结果如何？）
- 关键验证问题（你应该问创始人什么？）
- 红旗标识（哪些说法在物理/数学上不可能？）

```
"帮我评估一下这个创始人说的技术声称"
"这个公司说他们能做到X，靠谱吗？"
"pitch deck里的技术部分帮我过一下"
```

### 2. 能力边界分析 (Capability Frontier)

理解一项技术"能做什么"和"不能做什么"——这是投资判断的核心。

**框架**：
- **现在能做** → 已有产品/论文证明
- **理论上能做但还没做到** → 需要什么突破？timeline？
- **物理/数学上不可能** → 硬限制，不会随投入增加而改变
- **经济上不可行** → 技术可行但成本结构不支持商业化

```
"LLM现在能做什么不能做什么？边界在哪？"
"自动驾驶L4的真正瓶颈是什么？"
"蛋白质折叠预测到了什么阶段？"
```

### 3. 技术时机判断 (Timing Assessment)

最常见的投资错误不是"看错方向"而是"看错时机"。

**三问法**：
1. **为什么是现在？** → 什么底层变化让这件事在此刻可行？（成本曲线、算力、数据可得性、法规变化）
2. **为什么不是三年前？** → 三年前的瓶颈是什么？已经被解决了吗？
3. **为什么不是三年后？** → 如果等三年，机会更好还是更差？先发优势在技术领域有多重要？

```
"这个技术的timing对吗？"
"为什么这件事现在才可行？"
"如果等两年再投会怎样？"
```

### 4. 第二序效应思考 (Second-Order Effects)

投资人的核心技能不是"这个技术怎么工作"，而是"如果这个技术work了，世界会怎么变"。

**思维链**：
- 如果 [技术X] 成本降低10倍 → 哪些不可能的事变成可能？
- 如果 [技术X] 的精度提升到99.9% → 哪些行业会被重新定义？
- 如果 [技术X] 变得人人可用 → 谁受益最大？谁受损最大？
- 反向思考：如果 [技术X] 永远无法达到预期 → 什么替代方案会胜出？

```
"如果推理成本再降10倍，什么新应用会出现？"
"如果自动驾驶L5永远实现不了，谁赢？"
"agent真的work了，对SaaS意味着什么？"
```

### 5. 技术DD问题生成 (DD Question Generator)

在与创始人或CTO做技术DD之前，生成一组高质量的问题——让你在30分钟的对话中最大化信息获取。

**输出格式**：
- 5个必问问题（不管什么技术都要问的）
- 5个领域特定问题（根据具体技术定制）
- 3个红旗检测问题（专门设计来暴露夸大其词或知识盲区）
- 关键指标清单（你应该要求看到哪些数据？）

```
"我下周要见一个做AI code generation的团队，帮我准备技术问题"
"这个robotics公司要做DD call，生成一个问题清单"
"帮我设计几个能测试CTO技术深度的问题"
```

## 五个必问问题（通用）

无论评估什么技术，这五个问题永远有效：

1. **"你的技术和开源最佳方案相比，核心差异是什么？"**
   → 测试：是真正的技术壁垒，还是只是先发时间差？

2. **"如果OpenAI/Google明天做了你在做的事，你的护城河在哪？"**
   → 测试：数据护城河？分发优势？还是只是执行速度？

3. **"你的方法在scale上有哪些已知的限制？"**
   → 测试：创始人是否诚实地了解自己方法的边界？不知道限制 = 红旗。

4. **"你的inference成本结构是什么？能支撑你的定价吗？"**
   → 测试：技术可行 ≠ 经济可行。很多AI公司毛利是负的。

5. **"你团队中谁是这个技术方向最资深的人？他们为什么选择了你的方法而不是替代方案？"**
   → 测试：技术人才密度，以及他们是否深思熟虑过技术路线选择。

## 工作流

### 快速评估（15分钟）

1. 接收：创业公司名称/pitch deck/技术描述
2. WebSearch：搜索该公司、该技术方向、竞争对手
3. 输出：
   - 技术方向一句话总结
   - 可信度初判（高/中/低）+ 核心理由
   - 3个关键风险
   - 下一步建议（值得深入？直接pass？需要找什么样的专家验证？）

### 深度评估（2小时）

1. 快速评估的所有内容
2. 技术景观地图（该方向上的主要玩家、技术路线、关键论文）
3. 能力边界分析
4. 时机判断
5. 第二序效应分析
6. DD问题清单（15-20个问题）
7. 专家推荐（应该找什么领域的人验证？）

## 限制声明

Tech Oracle 不是技术专家。它的判断力来自：
- 大量公开技术文献的模式识别
- 历史类比匹配
- 结构化提问框架

它**做不到**的事：
- 评估非公开的核心技术细节（需要NDA + 专家审查）
- 替代hands-on的技术验证（需要实际跑benchmark）
- 预测基础科学突破的时间线（没人能做到）
- 在创始人刻意误导时识别所有谎言（需要人的直觉）

**最佳实践**：Tech Oracle 的输出是你与技术专家对话的起点，不是终点。AI给你80%的理解和正确的问题；最后20%的判断需要人——你信任的技术advisor + 你自己的直觉。
