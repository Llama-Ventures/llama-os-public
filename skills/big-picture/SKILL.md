# Big Picture — 物质世界的刻度感

> Agent 不能活在真空里。讨论任何东西之前，先知道这个世界的真实尺寸。

## 为什么需要这个

投资人和 agent 聊 startup 的时候，很容易飘在概念层——"这个赛道很大"、"市场在增长"、"有很多用户"。这些话没有刻度，等于什么都没说。

这个 skill 的作用：**让 agent 在讨论公司、行业、赛道时，自然锚定在真实世界的数字上。**

不是为了"证明"什么。过去存在的东西不意味着未来也会发生。但如果你连现在的世界长什么样都不知道，你的判断就没有地基。

## 何时触发

**主动触发（用户说）：**
- "这个市场有多大"
- "帮我感受一下规模"
- "big picture 是什么"
- "对标一下上市公司"
- "这个行业有多少人/公司/钱"
- "anchor 一下"

**被动触发（agent 自己判断）：**
- 对话中出现了一个行业/赛道/公司，但讨论缺乏规模感
- 用户在做判断但没有数字基础
- DD 过程中需要 context（配合 dd-partner / deal-evaluation 使用）

## 核心行为

### 0. 数据必须是最新的（Freshness First）

**这是最高优先级。** 每次触发 big-picture 时：

1. **先确认今天的日期**——你知道今天是几号
2. **去拿今天（或尽可能接近今天）的数据**——市值是实时的，融资是最近的，不是去年报告里的数字
3. **标注数据获取日期**——"NVIDIA 市值 $3.2T（2026-04-09）"，不是"NVIDIA 市值约 $X"
4. **如果只能找到旧数据，明确说出来**——"最新可获取数据为 2025Q3"，让用户知道这不是今天的快照

过时的数据比没有数据更危险——它给人一种"我知道"的错觉，但实际可能差了 2x。

### 1. 建立刻度（Calibrate）

给定一个话题（公司、行业、技术），从多个维度建立规模感：

| 维度 | 问什么 | 数据来源 |
|------|--------|----------|
| **市值** | 这个领域最大的上市公司值多少钱？前 10 名分别是谁？ | companiesmarketcap.com, 公开财报 |
| **收入** | 头部公司年收入多少？增速如何？ | 公开财报, 行业报告 |
| **人** | 多少人在这个领域工作？多少人消费这个东西？ | 行业统计, 政府数据, 调研报告 |
| **资金** | 最近融了多少钱？哪些公司拿了大轮？ | Crunchbase, PitchBook, 新闻 |
| **App/产品** | 头部 app 下载量多少？DAU 多少？收入排名？ | appark.ai, Sensor Tower, data.ai |
| **交易量** | 这个市场每年流转多少钱？ | 行业报告 |
| **增速** | 5 年前 vs 现在？趋势方向？ | 历史数据对比 |

不需要每次都覆盖所有维度。根据对话 context 判断哪些维度最有用。

### 2. 锚定而不是论证（Anchor, Don't Argue）

**做：**
- "目前 cybersecurity 领域最大的上市公司是 Palo Alto Networks，市值约 $120B。前五名加起来超过 $350B。"
- "全球约 420 万人从事 cybersecurity 相关工作，缺口约 350 万。"
- "2025 年 cybersecurity 领域风险投资约 $XX B，同比 +XX%。"

**不做：**
- "所以这个 startup 的 TAM 是 $500B"——这是分析，不是 calibration
- "这证明了这个赛道能出大公司"——过去不等于未来
- "市场很大所以值得投"——这不是你的判断

### 3. 规模阶梯（Scale Ladder）

当讨论一个具体公司时，可以构建一个阶梯帮助理解它"在哪"：

```
$1T+    Apple, Microsoft, NVIDIA
$100B+  [行业头部，列出 2-3 个]
$10B+   [成长期上市公司，列出 3-5 个]
$1B+    [独角兽，最近上市的，列出几个]
$100M+  [成长期私有公司，最近大轮融资的]
$10M+   [早期公司，seed/A 轮]
---
[讨论中的这个 startup] — 在这里
```

这不是在说"它会到哪"，是在说"世界的刻度是这样的，它现在在这个位置"。

### 4. 上市 vs 未上市全景（Listed vs Unlisted）

不要只看上市公司。一个赛道的真实全貌包含两边：

**上市公司（已被市场定价）：**
- 市值多少？收入多少？P/S 是多少？
- 这个赛道第一家上市的公司是谁？什么时候？IPO 时多大？
- 上市后表现如何？从 IPO 到现在涨了还是跌了？

**未上市公司（还在融资阶段）：**
- 最近哪些公司拿了大轮？估值多少？
- 跟上市公司比，估值倍数合理吗？
- 有没有即将 IPO 的？

**对比和计算（Do the Math）：**

这个 skill 不只是拉数字，要**做算术**：

- "赛道最大的上市公司 $40B，最大的未上市公司估值 $5B，差 8x——中间的空间是什么？"
- "头部上市公司 P/S 15x，这家 startup ARR $20M 增速 150%，按同样倍数是 $XX0M——现在融 $50M pre，如果保持增速 3 年约 $XX0M+ ARR"
- "这个赛道过去 3 年 VC 总投入 $8B，目前上市公司总市值 $200B，资金效率 25x"
- "从第一家公司成立到第一家 IPO 花了 X 年，目前最老的未上市公司成立 Y 年了"

算术不是预测，是让数字之间产生关系。单独一个数字是死的，数字之间的比例和差距才有意义。

### 5. 数据来源优先级（Detail in references/data-sources.md）

1. **公开市场数据**（最可靠）：市值、收入、财报 → companiesmarketcap.com, Yahoo Finance, 公开财报
2. **行业报告**（需要交叉验证）：市场规模、增速、人数 → Statista, IBISWorld, Gartner, 政府统计
3. **融资数据**（有偏差但有参考价值）：轮次、金额、估值 → Crunchbase, PitchBook, 新闻
4. **自己搜的**（标注来源和日期）：web search → 标注 ⚠️ 来源和获取日期

永远标注来源和时间。数据会过时，标注了至少知道是什么时候的快照。

### 6. 避免绝对化

遵循避免绝对性描述的原则：
- "目前主要的上市公司有..."（不是"所有上市公司"）
- "市场规模大约在..."（不是"市场规模是"）
- "公开数据显示约..."（不是"确切数字是"）

数字给的是量级感，不是精确值。$50B 和 $55B 的区别不重要，$50B 和 $500B 的区别才重要。

## 输出格式

不要固定模板。根据对话自然融入。但如果用户明确要求"帮我看看 big picture"，可以用这个结构：

```markdown
## [话题] — Big Picture

**市值锚点**
- [公司 A]: $XXB — [一句话定位]
- [公司 B]: $XXB — [一句话定位]
- ...

**规模感**
- 从业者：约 XX 万人
- 消费者/用户：约 XX 亿人
- 年度市场交易量：约 $XXB

**资金流向**
- 2025 年 VC 投资：约 $XXB
- 最近大轮：[公司] $XXM Series X
- ...

**量级判断**
[一两句话总结：这是一个什么量级的东西，跟什么可以类比]

> 数据来源：[列出来源] | 获取日期：YYYY-MM-DD
```

## 跟其他工作流的关系

这个 skill 是**基础设施**，不是独立流程。任何其他工作流都可以在需要的时候调用这个能力：

- **DD 早期** — 先 calibrate 再深入。"我们先看看这个赛道的大盘"
- **估值判断** — 评估估值合理性时，用 scale ladder 定位
- **行业地图** — 做行业认知地图时，用 big picture 打底；思考碰撞时，用真实数字锚定讨论

## 不做什么

- 不做 TAM/SAM/SOM 正式建模——quick math 可以，但不要装成精确的市场模型
- 不做 DCF 估值——这个 skill 给的是 context 和比例关系，不是 valuation report
- 不做预测——"未来会到 $XXB" 这种话不说
- 不把相关性当因果——"X 行业有 $500B 市值"不等于"所以这个 startup 能做大"
- 不用过时数据装最新的——找不到新数据就说"最新可获取为 YYYY-QX"
